## Chrome Web Store

1. Подготовить отдельный Google-аккаунт проекта, включить двухэтапную проверку,
   зарегистрировать разработчика и оплатить однократный сбор. На дату проверки
   Google указывает **5 USD**; окончательная сумма и доступность оплаты проверяются
   при регистрации. Потребуется принять условия магазина.
   [Регистрация](https://developer.chrome.com/docs/webstore/register),
   [размер сбора](https://developer.chrome.com/blog/cws-role-expansion-developer-dashboard),
   [двухэтапная проверка](https://developer.chrome.com/docs/webstore/using-api).
2. Указать издателя **Templar** и подтвердить контактную почту. Для расширений
   с покупками или подписками Google требует физический адрес. До регистрации
   проверить обязательные поля и их публичную видимость: отдельный GitHub-аккаунт
   не отменяет требования магазина к издателю.
   [Профиль разработчика](https://developer.chrome.com/docs/webstore/set-up-account).
3. Подготовить русскую карточку и английский перевод: описание одной функции
   браузерного VPN, обязательную действующую подписку, сайт и поддержку. Нужны
   PNG-иконка 128×128 и как минимум один актуальный скриншот; окончательные
   форматы проверить по [требованиям к изображениям](https://developer.chrome.com/docs/webstore/images).
4. Заполнить Privacy practices: объяснить каждое разрешение, включая `proxy`,
   `privacy`, `storage`, `alarms`, `<all_urls>` и Chromium webRequest-разрешения;
   указать фактическую передачу данных и публичный HTTPS-адрес политики.
   Поля должны соответствовать работе расширения и сервиса.
   [Анкета конфиденциальности](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy).
5. После разрешения на отправку загрузить **Chrome release ZIP**, заполнить
   Store listing, Privacy, Distribution и приватные Test instructions. Для
   проверки дать отдельный тестовый аккаунт с активной подпиской. Отправить на
   review; при необходимости выбрать отложенную публикацию. Срок и результат
   проверки не гарантированы.
   [Процесс публикации](https://developer.chrome.com/docs/webstore/publish).

## Firefox Add-ons

1. Подготовить Mozilla Account, подключить его к AMO Developer Hub и включить
   обязательную для разработчика двухфакторную защиту. Сохранить recovery-коды
   приватно, ознакомиться с Developer Agreement и Add-on Policies.
   [Подача расширения](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/),
   [требование 2FA](https://blog.mozilla.org/addons/2021/03/11/two-factor-authentication-required-for-extension-developers/).
2. Для карточки магазина выбрать **On this site**. Взять Firefox release ZIP/XPI
   с постоянным ID `templar-browser@templarvpn.com`; development-ID для магазина
   не использовать. Указать русский основной текст, английскую локализацию,
   поддержку, GPL-3.0-only, политику и необходимость платной подписки. Передать
   проверяющим отдельный аккаунт через приватные Notes for Reviewers.
3. Перепроверить `data_collection_permissions`: для новых расширений встроенное
   согласие Firefox обязательно. Текущий manifest заявляет `authenticationInfo`,
   `personallyIdentifyingInfo`, `browsingActivity`, `websiteContent`; эти категории
   должны соответствовать фактической передаче данных, в том числе прокси.
   [Согласие на передачу данных](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).
4. Приложить к версии соответствующий **source ZIP**, `package-lock.json` и
   точные команды сборки. Наш скрипт генерирует popup и конфигурацию, поэтому
   исходники нужны для воспроизведения. Указать версии инструментов и отдельно
   объяснить неизменённый DOMPurify и рассмотренное предупреждение линтера.
   [Требования к исходникам](https://extensionworkshop.com/documentation/publish/source-code-submission/).
5. Пройти валидацию/проверку AMO и получить подписанный файл. Затем проверить
   постоянную установку и полный перезапуск обычного Firefox. Временная установка
   неподписанного XPI такую проверку не заменяет. Решение о подписи и публикации
   принимает Mozilla; подпись не является обещанием отсутствия уязвимостей.
   [Подпись Firefox](https://support.mozilla.org/en-US/kb/add-on-signing-in-firefox).

## Локальная подготовка пакетов

Из чистого checkout выбранной версии, с Node.js 20+, npm 8+ и Python 3:

```sh
npm ci
npm test
npm run release:prepare
```

В `artifacts/release/` появятся:

| Файл | Назначение |
| --- | --- |
| `templar-browser-chrome-0.4.6-release.zip` | Кандидат загрузки в Chrome Web Store |
| `templar-browser-firefox-0.4.6-release.zip` / `.xpi` | Неподписанный кандидат для AMO |
| `templar-browser-source-0.4.6.zip` | Соответствующие исходники для reviewer |
| `SHA256SUMS` | Контроль целостности локальных кандидатов |

Команда не подписывает и ничего не загружает. При изменении версии имена файлов
изменятся автоматически. Подробности сравнения — [VERIFYING.md](../VERIFYING.md).
Токены магазинов, приватные ключи, пароли и recovery-коды не входят в репозиторий.
